# W1 — Telegram bot (aiogram 3.31)

Owns `apps/bot/` and `locales/bot.py`. Replace the placeholder `tulporgo_bot/handlers/__init__.py` with a package of
routers; keep exporting `router` and `setup(bot, maker, settings, bus)`.

## Checklist
1. **Start & language** — `/start` (deep links: `ref_<CODE>` → `referral.link`, `driver`, `faq`, `elon`, `obuna`);
   language picker on first start (5 options: Özbekça / Oʻzbekcha / Ўзбекча / Русский / English, decision 16) →
   `user.lang`; `/til` changes it. Greeting = approved texts from `content/i18n/build/telegram_texts.json`
   (`bot.start`, decision 40) with the tulpor-head emoji.
2. **Passenger order** (decision 47): (a) buttons: district → mahalla/place (inline pagination over `places`; search by
   typing), time (Hozir / Bugun / Ertaga + time), seats 1–4+, note; (b) free text → `tulporgo_core.parser.parse`; if
   parsed, show a confirmation card, else fall back to buttons; (c) Mini App button (`settings.miniapp_url`);
   (d) **Guest Mode** (Bot API 10.0, `supports_guest_queries`): when the bot is mentioned in a group, answer with
   `answerGuestQuery` — parse the route and offer a deep link to finish the order privately. aiogram may lack 10.0+
   types: use raw `bot.session` calls / `bot(TelegramMethod)` subclasses where needed and test them with a fake session.
3. **Driver notifications** — on `RequestCreated` notify `rides.matching_drivers` (rate-limit: Telegram ~30 msg/s,
   retry on 429), card with route, time (`date_time` entity where supported, plain text fallback), seats, price hint,
   women-only marker; buttons: "Taklif berish" → price input (quick prices around the hint + custom).
4. **Offers to the passenger** — each offer: car (make/colour/plate), driver rating, verified badge, price; buttons
   Accept (`style=success`) / Counter (decision 7) / Decline. Counter → driver gets Accept/Decline of the counter.
5. **Trip** — on accept: trip card to both (Rich Message `sendRichMessage` if available with a table: route, time,
   price, car; plain HTML fallback), driver phone/username exchange, "Share trip" link (`share_token`, decision 13),
   driver buttons Start / Complete / Cancel, passenger Complete / Cancel; after completion ask both for a 1–5 rating;
   complaint flow (`/yordam` → complaint text).
6. **Driver onboarding** — "Haydovchiman": phone via contact button (`request_contact`) → car make, colour, plate,
   seats, car photo, home district → `drivers.register_driver`; optional documents (license + techpass photos) →
   admin review → verified badge. Show referral link `t.me/<bot>?start=ref_<CODE>` and bonus rule (decision 52).
   Commands per scope: passengers `/start /qatnovlarim /til /yordam`; drivers additionally `/elon /obuna`
   (`setMyCommands` with `BotCommandScopeChat`).
7. **Admin panel** (decision 19, `user.is_admin` or `settings.admin_ids`): `/admin` → pending driver documents
   (approve → `drivers.verify`), open complaints (resolve), block/unblock user (blacklist), KPI now.
8. **Jobs** in `setup()`: expire requests (`rides.expire_requests`) every minute; weekly KPI report
   (`services.kpi.report`) to `settings.owner_chat_id` every Monday 09:00 Asia/Tashkent; members of the drivers group
   get member tags ("Tasdiqlangan", "Elchi") via `setChatMemberTag` when available (Bot API 9.5).
9. `/qatnovlarim` — passenger: open requests (cancel), trips history; driver: my offers, my trips.

## Done when
All flows above work end-to-end against a fake bot session in tests (passenger ↔ driver ↔ trip ↔ rating, counter
price, driver registration + verification + referral bonus, admin actions, guest query), with negative tests for
every permission/state rule, full suite + ruff green.

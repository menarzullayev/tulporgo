# W2 — Driver userbot service (Telethon 1.45)

Owns `apps/userbot/` and `locales/userbot.py`. Models already exist in core: `UserbotAccount`, `UserbotGroup`,
`UserbotPost` (encrypted session, limits, flood state). Decisions 8 and 48 are the law here.

## Checklist
1. **Consent** — before connecting, the driver sees a risk screen (auto-posting may get the account limited or banned
   by Telegram; TulporGo never bypasses FloodWait/PEER_FLOOD; "Hisobni uzish" deletes the session) and taps "Roziman"
   → `consent_at`. No consent → no login.
2. **Login without sharing codes in chat** — login runs from the Mini App form (W3 builds the page against your API):
   `POST /api/userbot/login/start {phone}` → Telegram sends the code to the driver's app;
   `POST /api/userbot/login/code {code}`; `POST /api/userbot/login/password {password}` when 2FA is on (never stored,
   never logged). The session string is encrypted with Fernet (`settings.userbot_encryption_key`) into
   `session_encrypted`. One account per driver; the Telegram user id is stored.
   Login codes typed into a Telegram message are blocked by Telegram — the API form is the only path.
3. **Groups** — list the driver's groups (dialogs that are groups/supergroups where they can write); driver picks them
   (Pro: ≤ 15, Business: unlimited, Basic: none; during the free period everyone = Business, see `billing.effective_plan`).
4. **Safe scheduler** (decision 48) — default ≥ 45 min (`userbot_min_interval_minutes`) per group + random jitter
   (`userbot_jitter_minutes`), optional daily cap; the driver may lower the interval only after an explicit risk
   acknowledgement (`risk_acknowledged`). Post text = driver template (route, time, seats, price, "@tulporgobot orqali
   bog'laning") built from i18n, never spam links.
   `FloodWaitError` → status `flood_wait`, `flood_until`, skip until then; `PeerFloodError`, `UserBannedInChannel`,
   `ChatWriteForbidden`, `AuthKeyUnregistered`, `UserDeactivated` → stop that group or the account (`stopped`, reason),
   publish `UserbotStopped`, notify the driver via the bot. Never retry in a loop.
5. **Bot UX** (`tulporgo_userbot.bot:router`, included by the bot): `/elon` menu — connect (opens Mini App login),
   status, groups on/off, interval, template preview, pause/resume, "Hisobni uzish" (log out + delete session).
6. **Worker** — `python -m tulporgo_userbot`: loads connected accounts, runs each client with its own Telethon
   session, schedules posts, listens for `UserbotStopped`/plan changes, graceful shutdown. Device model
   "TulporGo (driver)". Sessions decrypted only in memory.

## Done when
Consent → login (code + 2FA paths) → group selection → scheduled posting with limits → FloodWait/PeerFlood/ban
handling → logout, all covered by tests with a fake Telethon client (no network); negative tests for: posting before
consent, interval below the minimum without acknowledgement, plan group limits, posting during flood_wait, a stopped
account never posting again, session never stored or logged in plain text. Full suite + ruff green.

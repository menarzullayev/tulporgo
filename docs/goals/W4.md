# W4 — Payments and subscription (decision 44)

Owns `packages/payments/` (`tulporgo_payments`) and `locales/payments.py`. Core has `Payment`, plans and
`billing` (`price_of`, `create_payment`, `mark_paid` — idempotent, `subscription_active`, `effective_plan`,
`PaymentProvider` ABC, `in_free_period`). Everything is free while `settings.free_period_until` is in the future, but
every provider must be fully integrated and testable now (live keys come later — sandbox/test mode by default).

## Providers (`tulporgo_payments/providers/`)
1. **P2P card** — show `settings.p2p_card_number` / holder + amount + unique payment reference; driver uploads the
   receipt photo → `awaiting_review`; admins get the receipt with Approve (`style=success`) / Reject buttons →
   `billing.mark_paid` / `failed`. Only admins can approve; double approval is a no-op.
2. **Telegram Stars** — `sendInvoice` / `createInvoiceLink` with currency `XTR`, amount from
   `billing.stars_amount`; `pre_checkout_query` validation (payment exists, pending, amount matches) and
   `successful_payment` → `mark_paid` with `telegram_payment_charge_id`; recurring subscription link
   (`subscription_period=2592000`) where supported and `BotSubscriptionUpdated` (Bot API 10.2) handling.
3. **Click** (merchant API "Prepare/Complete"): signature `sign_string` MD5 check with `click_secret_key`, error codes
   per Click spec, idempotent complete, amount check; payment URL builder for the checkout button.
4. **Payme** (Merchant API JSON-RPC: CheckPerformTransaction, CreateTransaction, PerformTransaction,
   CancelTransaction, CheckTransaction, GetStatement): Basic auth with `payme_key`, amounts in tiyin, state machine and
   error codes per Payme spec, test mode flag; checkout URL builder (base64 params).
5. **Other** — a generic provider interface + one documented stub, so a new 3rd-party gateway is a single class.

## Bot UX (`tulporgo_payments.bot:router`, included by the bot)
`/obuna` (drivers): current plan + until date; during the free period say so clearly and offer nothing to pay;
otherwise plans (decision 10: Asosiy 29 000, Pro 59 000, Biznes 99 000 so'm/month) × months 1/3/6/12 (no invented
discounts) → provider choice → checkout. Notify the driver on success; remind 3 days before expiry (job hook
`setup_jobs(bot, maker, settings)` exported for the bot to call).

## API (`tulporgo_payments.api:router`, mounted under `/api/payments`)
`POST /api/payments/checkout` (Mini App auth via `tulporgo_api.deps.current_user`) → provider start payload;
`POST /api/payments/click/prepare`, `/click/complete`; `POST /api/payments/payme` (JSON-RPC). Webhooks are
idempotent, verify signatures/auth, never trust client amounts.

## Done when
Each provider has tests with recorded/fixture payloads incl. negative tests (bad signature/auth, wrong amount,
unknown payment, replayed callback, cancelled payment, non-admin approval, Stars amount mismatch), `/obuna` flows
covered with a fake bot, full suite + ruff green.
